The engine

Everything native. Nothing borrowed at runtime.

The official PyTorch/Diffusers implementation is used offline — to import model semantics and produce golden tensors we validate against. It never enters the runtime dependency graph.

⌘

Full-native pipeline

Native text encoder, 50-layer 33.1B DiT and 2D-ViT VAE decoder — MPSGraph graphs plus hand-written MSL kernels, fed by our own packed Q4 weights.

≠

Semantics ≠ execution plan

The model graph says what to compute; the planner decides residency, layouts, fusion, tiling and kernels for this machine. Frozen contracts never freeze optimization space.

⟲

Replayable by construction

Six versioned protobuf contracts (onyx.*.v1). Every run stores a RunRecord; outputs are verified by SHA-256, and replays reproduce the same bytes.

▦

Memory is part of the plan

135 GB of checkpoint weights staged into a 28.08 GiB budget: phase residency, block streaming, AdaLN precompute-and-release, VAE tiling. The runtime queries real Metal limits, never guesses.

✓

Evidence-first optimization

A candidate is accepted only with measurement JSON, correctness gates and an output-hash proof. Round 1 of our optimization loop made things slower — and we published it.

⊗

No implicit behavior

No prompt rewriting, no silent network, no silent quantization, no silent disk swap. If the engine wants to do something you didn't ask for, it asks first.

gap · published

Q4 GEMM kernel vs MLX. Our tile16 kernel runs 28.12 ms median on 1024×5376×5376 (group 64) against MLX quantized_matmul's 1.71 ms — a 16.5× gap, measured and committed rather than omitted.

gap · published

Community W8A8 path. Same 1024 teapot request: community MLX pipeline 23.61 s, native Onyx 38.74 s — 1.64× apart, with different quantization and execution. That's the next optimization target.

fidelity

Numerical references hold. Text tower correlation 0.9999987 vs FP32 reference, VAE pixel correlation 0.999993, and all four optimization rounds reproduce the same output SHA-256 byte-for-byte.

Quick start

From clone to native generation

Build Onyx locally and prepare the W4 model files before generating an image.

System

Apple Silicon Mac with macOS 26.2 or later, the Xcode Metal 4 toolchain, and uv with Python 3.12 or later.

Disk

About 62 GB for the W4 inference files, including the VAE, PDD heads, and tokenizer. For local conversion, allow about 200 GB for the original checkpoint and converted model, plus space for build tools.

Memory

Tested at 1024×1024 on Macs with 24 GB and 36 GB of unified memory. Sampled peak process-tree RSS was about 2 GB at this resolution. The minimum supported unified memory is unverified.

Measured generation time

Six-step W4 teapot benchmarks, seed 42, with the optional DiT caches and prefetch disabled. Resident set size (RSS) is sampled across the inference process tree.
